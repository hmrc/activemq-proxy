
# activemq-proxy

A backend microservice that isolates other DASS services from ActiveMQ. Rather than each service embedding its own JMS connection code and config, they POST a message to this proxy and it publishes to the appropriate ActiveMQ queue. It follows the same principle as the RDS database proxies.

Introduced during phase 1 of the DASS replatforming for the services that still write to ActiveMQ (AccountMgmt, EUVAT, MGD, Notice Viewer, NOVA, ERS).

## Endpoint

### `POST /queue/send`

Publishes a message to one of the permitted queues.

**Request body**

```json
{
  "queueIdentifier": "AGENT_Filing_APRQ",
  "payload": "<?xml version=\"1.0\" encoding=\"UTF-8\"?>...",
  "properties": [
    { "key": "MESSAGE_CLASS", "value": "HMRC-AGENT-APR" },
    { "key": "LOB", "value": "Agent" }
  ],
  "correlationId": "54947df80e9e4471a2f99af509fb5889"
}
```

| Field | Description | Optionality | Type |
|---|---|---|---|
| `queueIdentifier` | Target queue. Must be one of the permitted values below. | Required | String |
| `payload` | The message body sent to the queue (typically a ChRIS XML string; any string is accepted). | Required | String |
| `properties` | JMS message properties as key/value pairs, attached as string properties. Omit if none are needed. | Optional | List |
| `correlationId` | Unique request id. Must be **exactly 32 characters** if supplied; otherwise one is generated (`UUID.randomUUID().toString.replace("-", "")`). | Optional | String |

**Permitted `queueIdentifier` values**

`AGENT_Filing_RCLQ`, `AGENT_Filing_UORQ`, `SS_Filing_TrackingQ`, `NOVA_AuditShipping_IncomingQ`, `AGENT_Filing_APRQ`, `AGENT_Filing_AARQ`

**Response** — `200 OK`

```json
{ "correlationId": "54947df80e9e4471a2f99af509fb5889" }
```

`correlationId` is the id used for the published message — either the one supplied in the request or the one generated by the proxy.

**Authorisation**

The endpoint is protected by HMRC auth. The caller must pass a bearer token (`Authorization: Bearer <token>`) for a user who is:

- **logged in** (has an active session), **and**
- of the **Agent** affinity group, **and**
- holds an active **`HMRC-MGD-AGNT`** enrolment with a **`HMRCMGDAGENTREF`** identifier.

**Error responses**

| Status | When |
|---|---|
| `400 Bad Request` | Body is not JSON / missing `payload` or `queueIdentifier` / unknown `queueIdentifier` / `correlationId` not exactly 32 chars |
| `401 Unauthorized` | No active session (missing/expired bearer token) |
| `403 Forbidden` | Logged in but not an Agent, or Agent without an active `HMRC-MGD-AGNT` enrolment |
| `415 Unsupported Media Type` | `Content-Type` is not `application/json` |
| `500 Internal Server Error` | The message could not be published to the broker |

> Note: the service is mounted under the `/activemq-proxy` context, so the full path when calling it directly is `POST /activemq-proxy/queue/send`.

## Configuration

The broker connection is a single URL (`jms.brokerUrl`), following the same convention as `mongodb.uri` — a local default in `application.conf`, overridden per environment in `app-config-<env>`. There is no JMS username/password; reconnect/failover options are carried in the URL itself:

```hocon
jms.brokerUrl = "failover:(tcp://host-1:61616,tcp://host-2:61616)?maxReconnectAttempts=3&startupMaxReconnectAttempts=100&timeout=5000&jms.sendTimeout=5000"
```

The default in `application.conf` points at a local broker: `tcp://localhost:61616`.

## Running locally

Running locally involves **two separate processes**:

1. the **ActiveMQ broker** — the `prh-activemq` Docker container, on `tcp://localhost:61616` (see [Local ActiveMQ broker](#local-activemq-broker) below);
2. **this service** — a `sbt run` JVM on `http://localhost:10406`.

Starting the container does **not** start the service. The `POST /queue/send` calls go to port **10406** (this service), which then publishes to the broker on **61616**. If port 10406 refuses the connection, the service isn't running — start it with `sbt run`.

With the broker container already up, start the service:

```bash
sbt run
```

The service starts on port `10406`. The endpoint requires an Agent bearer token (see [Authorisation](#authorisation)) — locally you can grab the `Authorization` header from **auth-login-stub** (log in as an Agent with an active `HMRC-MGD-AGNT` enrolment).

With `sbt run` still running in that terminal, smoke test from another terminal (`$TOKEN` is that bearer token):

```bash
curl -sS -X POST http://localhost:10406/activemq-proxy/queue/send \
  -H "Authorization: ${token from auth-login-stub}" \
  -H "Content-Type: application/json" \
  -d '{
    "queueIdentifier": "AGENT_Filing_APRQ",
    "payload": "<test/>",
    "properties": [{"key":"MESSAGE_CLASS","value":"HMRC-AGENT-APR"}]
  }' \
  -w '\nHTTP %{http_code}\n'
# -> {"correlationId":"<generated-32-char-id>"}
#    HTTP 200
```

`-sS` still prints errors (unlike `-s` alone), and `-w` shows the status code — so if the app isn't running you'll see `curl: (7) Failed to connect ...` rather than a blank line. `sbt run` is ready once it logs `Application started`. Without a valid Agent token you'll get `401` (no token) or `403` (not an Agent / missing `HMRC-MGD-AGNT` enrolment).

You can confirm the message arrived by following the broker's logs (`docker logs -f prh-activemq`).

### Local ActiveMQ broker

The proxy talks to the [`hmrc/prh-activemq`](https://github.com/hmrc/prh-activemq) container (ActiveMQ 6.0.1 with an embedded Camel router that logs messages on the relevant queues).

**Prerequisites:** Docker Desktop running, and GitHub access to `hmrc/prh-activemq`.

```bash
# 1. Clone and build the image (first build downloads ActiveMQ, ~1 min)
git clone git@github.com:hmrc/prh-activemq.git
cd prh-activemq
./build

# 2. Run the container (publishes 61616 = JMS/OpenWire, 8161 = web console)
./run

# 3. Wait until ready — look for "Apache ActiveMQ 6.0.1 (localhost, ...) started"
docker logs -f prh-activemq
```

**Fix the web console binding (required to reach the console).** Out of the box the console's Jetty binds to `127.0.0.1` inside the container, so `localhost:8161` is unreachable from the host. Patch it once and restart:

```bash
docker exec prh-activemq sed -i 's|value="127.0.0.1"|value="0.0.0.0"|' \
  /opt/apache-activemq-6.0.1/conf/jetty.xml
docker restart prh-activemq
```

This survives `docker restart` but is lost if you re-run `./run` (which recreates the container) — just re-apply it.

**Access:**

| What | How |
|---|---|
| Web console | http://localhost:8161/admin — user `admin` / pass `admin` |
| JMS / OpenWire (for this service) | `tcp://localhost:61616` — no credentials |

> Don't open `localhost:61616` in a browser — it's a binary JMS port, not HTTP. It only responds to a JMS client, and the broker will log `Frame size of 1 GB larger than max allowed` for a browser request.

Messages sent to `SS_Filing_TrackingQ`, `AGENT_Filing_AARQ/APRQ/RCLQ/UORQ` (and `pev`, `peq`, `tracking`, etc.) are consumed and logged by the embedded Camel router. `NOVA_AuditShipping_IncomingQ` has no consumer, so messages sit on it — useful for inspecting a message's headers/properties in the console.

## Tests

```bash
sbt test                                  # unit tests
sbt clean coverage test coverageReport    # tests with coverage report
```

The service tests spin up an embedded in-process broker (`vm://`), so they do **not** require Docker.
